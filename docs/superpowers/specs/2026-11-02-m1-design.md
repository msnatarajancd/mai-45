# ReadyRelief M1 application design

Authority: the team's ReadyRelief_Plan.docx (5-person MVP delivery plan), supplied November 2. This implements the requested M1 work within that existing plan. The older static prototype is not the application foundation.

## Intent
Give a fictional Miami-Dade household a clear next step before, during, and after a hurricane/flood. Deliver a memorable, repeatable contest demonstration while accurately showing which team services are connected.

## Approach
Use the existing Python/Streamlit repository and M5 domain/repository services. A separate React application would split the team's delivery; embedding the older static prototype would duplicate state. A custom Streamlit presentation layer with native accessible controls gives the best integration path. This is the implementer's choice within the master's recommendation.

## Experience
Warm ivory canvas, deep forest navigation, teal actions, amber simulation badges, coral emergency controls. Home has three clear entry cards and a household journey illustration. Persistent emergency controls precede service calls. Pages: Home, Protect, Respond, Recover, Household, and Evidence. A sidebar demo guide follows the Rivera household. No maps, accounts, notifications, or invented impact metrics.

## Boundaries
Default to SIMULATED DEMO. LIVE CHECK never renders fixtures. M2 alerts, M3 retrieval/directory, and M4 routing have typed replaceable adapters with honest unavailable states. Basic conservative emergency access works without those integrations. M5's existing case/plan/task/reassessment APIs are used directly, with a separate UI and no changes to its data model. Recovery remains a fictional local demo in either alert mode. Optional experimental AI uses M5's existing Nebius adapter, with its grounding disclosure.

Household input is optional, synthetic, session-only, and never gates emergency access. Supported area changes clear location-specific results. Mode changes clear alert/guidance state. A household switch does not silently rewrite an accepted recovery case. Recovery requires explicit danger assessment and approval. SQLite persists only fictional recovery cases; users retain case IDs to resume after reload. Hosted local disk is not promised durable or private multi-user storage.

## Acceptance
All screens reachable; keyboard-accessible native widgets; responsive desktop/mobile layout; simulation and failure states honest; emergency access available with broken storage/services; one complete approved and persisted recovery journey; reassessment preserves completed tasks; existing M5 tests remain green. README, integration ownership TODOs, demo script, and test evidence accompany delivery. No claim of contest parity or real-world emergency validation.
